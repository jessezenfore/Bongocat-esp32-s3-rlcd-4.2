# 串口通信协议 (Bongo Cat RLCD)

电脑端脚本与开发板之间通过 **USB CDC 串口** 通信，使用行文本协议：每条消息一行，
字段用英文逗号 `,` 分隔，以 `\n` 结尾（`\r` 会被忽略）。全部为 ASCII，方便用任意
串口助手手工调试。

- 串口参数：`115200 8N1`（ESP32-S3 原生 USB-CDC 实际忽略波特率，但两端需一致）
- 板子 → 电脑：`READY` / `HB` / `PONG` / `ERR`
- 电脑 → 板子：`HELLO` / `T` / `S` / `A` / `PING`
- 单行最长 96 字节，超长行会被丢弃并在下一个 `\n` 重新同步

---

## 电脑 → 开发板

### `HELLO` — 握手

```
HELLO,<协议版本>,<主机名>
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 协议版本 | int | 当前为 `1` |
| 主机名 | string | 显示在屏幕左下角，最长 19 字符 |

脚本在串口打开后立即发送一次，之后每 30 秒重发一次（这样开发板中途重启也能自己恢复
主机名，不需要重启脚本）。板子每收到一次 `HELLO` 都会回复一次 `READY`。

### `T` — 校准时钟

```
T,<Unix 时间戳>,<时区偏移分钟>
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| Unix 时间戳 | int64 | **UTC** 秒数（`time.time()`） |
| 时区偏移分钟 | int | 本地时间相对 UTC 的偏移，例如东八区为 `480` |

脚本每秒发送一次。板子不以自己的 RTC 为准，而是记录 `收到时刻 = millis()`，
之后用 `millis()` 递增推算当前时间，因此断连后仍能继续走时，重新连上即自动校准。

### `S` — 负载与网速

```
S,<CPU 占用>,<内存占用>,<下行速率>,<上行速率>
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| CPU 占用 | float | `0`–`100`，百分数 |
| 内存占用 | float | `0`–`100`，百分数 |
| 下行速率 | uint | **字节/秒**（所有非回环网卡接收之和） |
| 上行速率 | uint | **字节/秒**（所有非回环网卡发送之和） |

脚本默认每 1 秒发送一次（`--interval` 可调）。超过 5 秒没收到新样本，屏幕上的
数值会显示为 `--`。

### `K` — 猫爪状态（原版行为）

```
K,<左爪是否按下>,<右爪是否按下>
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 左爪是否按下 | 0/1 | 主键盘区（字母、数字、空格、修饰键……）有键按住时为 1 |
| 右爪是否按下 | 0/1 | 方向键（↑↓←→）有键按住时为 1 |

这一条直接对应原版 BongoCat 的两个 Live2D 参数
`CatParamLeftHandDown` / `CatParamRightHandDown`。原版用按键素材所在目录来区分：
`resources/left-keys/` 里是 55 个主键盘按键，`resources/right-keys/` 里只有 4 个方向键，
按下哪一组，对应的爪子就压下去。

脚本默认每秒发送 20 次（`--activity-hz` 可调）。持续发送而不是只在变化时发送，
是为了让板子断线重连后能自己恢复正确姿势。

### `A` — 键盘活跃度

```
A,<每秒按键数>
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 每秒按键数 | float | 最近 2 秒滑动窗口内的平均按键速率 |

只用来在屏幕左上角显示 `NNN keys/min`，不参与猫咪动作。默认同样每秒 20 次。

### `B` — 屏幕横幅（电脑消息）

```
B,<x>,<y>,<w>,<h>,<持续毫秒>,<base64 位图>
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| x, y, w, h | int | 目标矩形（400×300 横屏坐标） |
| 持续毫秒 | int | 到时间自动消失；`0` 表示一直显示直到被清除 |
| base64 位图 | string | 1-bit XBM 数据，见下 |

**为什么传位图而不是文本**：面板上的 U8g2 字体没有中文字形，而装一套 CJK 字体
会把 flash 撑爆。所以由电脑端把文字（任意语言、任意字体）先渲染成位图再发过来。

位图格式与 U8g2 `drawXBM()` 一致：每字节**低位在前**，行按字节对齐，
**bit=1 表示「墨」**。固件会先用「纸色」铺满整个矩形，再把 bit=1 的点画成墨色，
所以 bit=0 的位置就是干净背景——横幅正是靠这一点盖住后面的猫和键盘。

这条消息是**很长的行**（384×64 约 4.1 KB base64），所以固件的行缓冲（6 KB）和
USB 接收队列（8 KB）都比普通消息大得多。建议只在提示类场景使用，别高频发送。

### `BC` — 清除横幅

立即隐藏当前横幅。

### `PING`

连通性测试，板子回复 `PONG`。

## 开发板 → 电脑

### `READY` — 启动完成 / 握手应答

```
READY,<固件名>,<固件版本>
```

例如 `READY,BongoCat-RLCD,1.0.0`。板子上电时主动发送一次，之后每收到一次
`HELLO` 也会回复一次。
### `HB` — 心跳

```
HB,<运行毫秒数>,<刷新率 ×10>
```

板子每 5 秒发送一次，可用来确认双向链路是否正常（例如 `HB,25000,118` 表示
开机 25 秒、当前刷新率 11.8 fps）。

### `PONG`

对 `PING` 的应答。

### `ERR` — 错误

```
ERR,<原因>
```

目前只有一种：`ERR,bad-line`（收到无法识别的行）。电脑端可以据此排查协议不匹配。

## 时序

```
电脑                                    开发板
 │  ── 打开串口 ─────────────────────────►│
 │  ── HELLO,1,DESKTOP-ABC ─────────────►│
 │  ◄──────────────── READY,BongoCat-RLCD,1.0.0
 │  ── T,1757400000,480 ────────────────►│   每秒
 │  ── S,37.2,61.5,120400,8300 ─────────►│   每 1 秒
 │  ── K,1,0 ───────────────────────────►│   每 50 毫秒
 │  ── A,4.50 ──────────────────────────►│   每 50 毫秒
 │  ◄──────────────── HB,5000,120        │   每 5 秒
```

## 手工调试

不需要电脑端脚本也能验证硬件：

```powershell
# Windows：用内置的 .NET 串口对象发几行
$p = New-Object System.IO.Ports.SerialPort COM7,115200
$p.Open()
$p.WriteLine("HELLO,1,ManualTest")
$p.WriteLine("T,$([int][double]::Parse((Get-Date -UFormat %s))),480")
$p.WriteLine("S,42,55,1200000,30000")
$p.WriteLine("A,6")
Start-Sleep 1
$p.ReadExisting()
$p.Close()
```

也可以把 `bongocat_host.py` 当作协议参考实现，用 `--print-only` 只看它发出的内容。
